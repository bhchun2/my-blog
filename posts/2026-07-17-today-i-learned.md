클로드 코드와 함께 프레임워크 없이 블로그를 만들면서, 세 언어가 각자 어떤 역할을 맡는지 다시 한번 체감했습니다.

## HTML — 구조와 의미

HTML은 콘텐츠에 **의미**를 부여하는 역할을 합니다. `<article>`, `<header>`, `<time>` 같은 시맨틱 태그를 쓰면 브라우저와 스크린 리더가 "이건 글이다", "이건 날짜다"를 이해할 수 있습니다. 이번 블로그에서는 `index.html`(목록)과 `post.html`(상세) 두 개의 문서로 역할을 나눠서, 각 페이지가 자기 콘텐츠에 맞는 `<title>`을 가질 수 있게 했습니다.

## CSS — 표현과 적응

CSS는 같은 HTML을 다른 모습으로 보여주는 역할을 합니다. 이번에 가장 크게 느낀 건 **CSS 커스텀 프로퍼티**의 힘이었습니다.

```css
:root {
  --color-bg: #ffffff;
}

@media (prefers-color-scheme: dark) {
  :root {
    --color-bg: #14161a;
  }
}
```

색상을 변수로 추상화해두면, 다크모드는 결국 "변수 값만 바꿔치기"하는 문제가 됩니다. 반응형도 마찬가지로, `min-width` 미디어 쿼리 몇 개로 카드 목록이 1열에서 2열로 자연스럽게 바뀌었습니다.

## JavaScript — 동작과 데이터

JavaScript는 정적인 HTML/CSS에 **움직임**을 더합니다. 이 블로그에서는 크게 세 가지 일을 시켰습니다.

1. 마크다운 파일을 fetch로 가져와서 HTML로 변환하기
2. 검색어와 태그에 따라 화면을 다시 그리기
3. 다크모드 선택을 localStorage에 저장하고 복원하기

프레임워크 없이 바닐라 JS만 쓰다 보니, "상태가 바뀌면 화면을 어떻게 다시 그릴지"를 직접 관리해야 했습니다. 리액트 같은 도구가 자동으로 해주던 일을 눈으로 직접 보면서, 그 도구들이 왜 필요한지도 거꾸로 이해하게 됐습니다.
